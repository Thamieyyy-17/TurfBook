TURFBOOK IMPLEMENTATION NOTES

Authentication and roles
- Customer: no account; a booking is accessed using its booking document ID plus a random 20-character hex access code. Only the hash is stored in Firestore.
- Admin: Firebase Google sign-in; the authenticated UID must have admins/<UID> with active=true. There is no bootstrapAdmin function or setup secret. Android uses the native Google picker via the Capacitor Firebase Authentication 6.x plugin and bridges its ID token into Firebase JS Auth; web uses the JS popup. Add SHA-1 and replace google-services.json with the OAuth-populated file before Android sign-in tests. Plugin 6.x is deprecated upstream and should be upgraded with Capacitor 8 before production.
- Owner: Firebase Auth account generated by a trusted function; ownerId custom claim and active owner document are both checked by protected functions.

Booking safety
- createBooking validates future date/time, active turf, supported format, positive configured price, and exactly ten phone digits.
- For each booked hour it creates a deterministic slotLocks document in the same Firestore transaction as the booking. Existing bookings are also checked to avoid overlaps with pre-lock records.
- Declined requests release their slot-lock documents. Approved bookings retain the locks.

Payments and credit
- Customer can submit a UPI reference only after approval, with their booking access code.
- Admin verifies the payment. The backend adds ₹50 in an idempotent ledger entry, so repeated verification cannot duplicate the credit.
- This is not a bank split/payout. No money is automatically transferred to an owner.

Turf constraints
- Server rejects a turf without both 5s and 7s and their positive, separate prices.
- Mini 7s may appear on only one turf, with its own positive price.
- The admin must enter actual local prices and select which turf offers Mini 7s; no real-world rates are guessed.

Notifications
- Firestore triggers create owner/admin notification records and send FCM to registered owner/admin devices and the optional guest token.
- Native Android channel uses the included turfbook_alert sound. Foreground app code plays the local tone and vibrates where supported.
- FCM delivery requires deployment, configuration, permission and on-device testing.

Storage
- Compressed turf/QR/app/notice images are stored as bounded data URLs in Firestore documents to avoid relying on a Storage bucket in this source revision. Per-document and combined payload limits are validated. For larger image libraries, migrate to a secured Storage upload architecture before production.

Deployment limitations
- Cloud Functions require Blaze billing. Do not activate billing without a parent/guardian reviewing it.
- The source ZIP cannot deploy to Firebase by itself. A Firebase CLI account with project access is required.
- Android Google OAuth native sign-in needs SHA fingerprints and OAuth client configuration; the included google-services.json does not contain Android OAuth client entries yet. The Capacitor Firebase Authentication 6.x package is used for the current Capacitor 6 app but is deprecated upstream.
- The included workflow builds a debug APK, not a signed Play Store release. The local authoring environment could not download npm dependencies, so build verification remains pending.
